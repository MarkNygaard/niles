> Interface 0.6 is the current source contract, but is not yet a released
> compatibility promise. It adds tracked [`notify.request`](#notify) and
> `notify.status` to interface 0.5. Interface 0.5: 0.1 plus [`mqtt`](#mqtt) and its two exports (0.2.0),
> `config.time-zone` and `devices.set-room-light` (0.2.1), and
> [`secrets`](#secrets), [`inbound`](#inbound) and three exports for
> [accounts and webhooks](/docs/writing-add-ons/accounts) (0.3),
> [WebSockets](/docs/writing-add-ons/websocket) (0.4), and
> [speech streams](#speech-stream) (0.5). Interface 0.5 remains supported.
> The examples compile against
> [`niles-integration.wit`](https://github.com/MarkNygaard/niles/blob/main/schemas/niles-integration.wit) with
> `wit-bindgen` 0.63; the WIT file is the authority. Each plugin targets one
> interface version in its manifest and imports only the functions in that
> WIT world. Niles continues to run frozen 0.4 and older worlds; see
> [interface versions](/docs/writing-add-ons/publishing#interface-versions).

A plugin **imports** functions Niles provides and **exports** functions Niles
calls. Examples are Rust; in JavaScript and Python the names are the same in
camelCase and snake_case (see the [worked example](/docs/writing-add-ons/example-spotprice#the-same-tool-in-javascript-and-python)).

Rules that hold for every call:

- **One call at a time.** Niles never calls into your plugin twice at once,
  and never while your plugin is inside a host call. Global state needs no
  locks; `thread_local!` with a `RefCell`, or a `static Mutex`, is fine.
- **Calls have deadlines**: 10 s for most exports, 30 s for `init`, 3 s for
  `render`, 2 s for `stop`. Time spent waiting in host calls counts. Past the
  deadline the instance is thrown away and restarted with backoff.
- **Your instance can disappear** after a trap, a timeout, a settings change
  or an update. Anything that must survive goes in [storage](#storage).

In Rust, records passed to imports are borrowed when they contain strings or
lists (`&Request`, `&Device`, and `&DeviceState`, whose `readings` is a list)
and passed by value when they do not. wit-bindgen does not derive `Default`;
keep an `empty_state()` helper for `DeviceState`, with `readings: Vec::new()`
(see the worked example).

## Exports: what you implement

### `init() -> result<_, string>`

Called once per instance: when the plugin starts, after every settings change,
after a restart. 30 seconds. Read your settings, register devices, set timers,
subscribe to events. Do not assume a fetch will succeed here; a device that is
off at boot should leave you "working, device unavailable", not "not working".

An `err` becomes the plugin's status line, so write it for the person reading
the card: `Err("The address is not set.".into())`. Niles retries when settings
are saved and every 10 minutes.

### `tools() -> list<tool-def>`

Read after each successful `init`. Return `Vec::new()` for none. See
[tools](/docs/writing-add-ons/tools).

### `call-tool(name, args-json) -> result<string, string>`

`name` is the bare name from your `tool-def` (`prices`, not `spotprice_prices`).
`args-json` is a JSON object the model produced against your schema; parse it,
and do not trust it further than that. `ok` is what the model reads; `err` is
told to the model as the tool's failure, so it can say "The bus service isn't
answering" rather than nothing.

### `set-device(id, desired) -> result<_, string>`

For your controllable devices only. `desired` holds just the fields to change.
Send the command, and once the device confirms, report the new state with
`devices::report_state`; the app shows the change as soon as it is asked for
and settles it when you report. See [devices](/docs/writing-add-ons/devices#controllable-devices).

### `on-timer(id)`

A timer you set fired. If the previous call for the same timer id is still
running, this one is skipped rather than queued, so a slow poll cannot pile up.

### `on-event(event)`

An event you subscribed to. See [events](#events).

```rust
fn on_event(event: Event) {
    match event {
        Event::DeviceState(change) if change.state.open == Some(true) => {
            // change.id is the full id, e.g. "z2m:office/door"
        }
        Event::DeviceAction(press) => { /* press.id, press.action */ }
        Event::Presence(HomeState::Away) => { /* nobody home */ }
        _ => {}
    }
}
```

### `render(surface-id, context) -> result<ui-tree, string>` and `on-action(...)`

Pages and widgets. See [pages and widgets](/docs/writing-add-ons/ui).

### `on-mqtt-message(conn, topic, payload)` and `on-mqtt-status(conn, status)`

New in 0.2. A message on a topic one of your MQTT subscriptions matches, and
a change in a connection's state: `connected`, `disconnected(why)` while Niles
reconnects, `failed(why)` when it stopped trying, `certificate-changed` when a
device's certificate is not the one trusted before. A plugin that uses no MQTT
still exports both, empty. See [MQTT](/docs/writing-add-ons/mqtt).

### `authorize-url(callback-url, state)`, `on-callback(callback-url, query, person)` and `on-webhook(request)`

New in 0.3: connecting an account through a service's sign-in page, and
answering a webhook. A plugin that does neither still exports all three:
`authorize-url` returns an `err`, and `on-webhook` a `404`. See
[accounts and webhooks](/docs/writing-add-ons/accounts).

### WebSocket callbacks

Interface 0.4 exports `on-websocket-message` and `on-websocket-status`.
See [WebSockets](/docs/writing-add-ons/websocket) for the complete API and lifecycle.

### `stop()`

The instance is about to go: Niles is stopping, or the plugin is being
updated, disabled, removed or restarted for new settings. Two seconds. Nothing
is guaranteed to run after it, and a crash skips it, so do not rely on it to
save anything important.

## Imports: what Niles provides

### `log`

```rust
use niles::integration::log;

log::log(log::Level::Info, "polling the inverter");
```

Levels `Debug`, `Info`, `Warn`, `Error`. Lines go to Niles's log, tagged with
your id, and to your card's log in the app (the last 1,000). At most 100 lines
per 10 s and 2 KiB each; beyond that lines are counted, not kept. Stdout and
stderr (`println!`, `eprintln!`, a panic message) also land here, as info and
warn.

### `config`

```rust
use niles::integration::config;

let address = match config::get("address") {
    Some(config::SettingValue::Text(address)) => address,
    _ => return Err("The address is not set.".into()),
};
let key: Option<String> = config::secret("api_key");
```

`get` returns what the user entered, else the manifest's `default`, else
`None`. `choice` and `room` settings come back as `Text`. `secret` returns
`secret` settings only; `get` returns `None` for them. Asking for a key the
manifest does not declare returns `None` and logs a warning, which is how
typos show up.

```rust
let zone: String = config::time_zone(); // "Europe/Copenhagen"
```

`time_zone` (0.2.1) is the house's time zone, an IANA name, from Niles's own
configuration (`[home] timezone`), so a plugin can say "done at 14:30" in
the household's clock without a setting of its own. WASI's clock is UTC;
convert with a time-zone crate such as `chrono-tz`, or `jiff`, built for
`wasm32-wasip2`. Read it when you need it rather than once in `init`: the
household can change it while your plugin runs. Under `niles plugin dev` it
is your machine's zone, or `--time-zone`'s.

### `storage`

A private key-value store of strings, kept in Niles's database. Nobody else
can read it; removing the plugin deletes it.

```rust
use niles::integration::storage;

storage::set("cursor", "2026-10-14T12:00:00Z").map_err(|e| format!("{e:?}"))?;
let cursor: Option<String> = storage::get("cursor");
for key in storage::list_keys("day:") {
    storage::delete(&key);
}
```

Keys up to 256 bytes. All keys and values together up to 1 MiB; a `set` that
would go over fails with `HostError::Limit`. Keys starting with `.niles/` are
Niles's own, kept for your plugin (the certificates [MQTT](/docs/writing-add-ons/mqtt) trusts):
they are not listed, and reading or writing one fails, but they count towards
the 1 MiB. Store JSON with `serde_json` when
you need structure. `list_keys` returns keys in sorted order, so date-stamped
keys (`day:2026-10-14`) list oldest first.

### `http`

One request, the whole response.

```rust
use niles::integration::http;

let response = http::send(&http::Request {
    method: http::Method::Post,
    url: "https://api.example.com/v1/login".into(),
    headers: vec![("content-type".into(), "application/json".into())],
    body: Some(br#"{"user":"me"}"#.to_vec()),
    timeout_ms: None,
});
match response {
    Ok(r) if r.status == 200 => { /* r.body is Vec<u8> */ }
    Ok(r) => return Err(format!("The service answered {}.", r.status)),
    Err(http::HttpError::Timeout) => return Err("The service did not answer in time.".into()),
    Err(e) => return Err(format!("{e:?}")),
}
```

- The host must be in your manifest's `http` list, exactly or under a
  `*.example.com` wildcard, or covered by `local_network`. Otherwise:
  `HttpError::NotPermitted`.
- After DNS, the address is checked again. Private, loopback and link-local
  addresses (`192.168.x.x`, `10.x.x.x`, `127.0.0.1`, `169.254.x.x`, and their
  IPv6 kin) are refused unless `local_network` names them, whatever the host
  name says.
- Internet hosts must be `https`. Plain `http` is allowed to local-network
  addresses only.
- Redirects are followed, up to 5, each checked the same way.
- A 404 or 500 is an `Ok` response with that status; only failures to get an
  answer are errors: `Timeout`, `Connection` (DNS, refused, TLS),
  `TooLarge` (over 4 MiB), `InvalidRequest`.
- `timeout_ms` defaults to 5,000 and is cut to whatever is left of the
  current call's deadline.
- Niles adds `user-agent: niles-plugin/<id>/<version>` unless you set one.
  No cookies are kept between requests; if a service needs a session, keep
  its token in storage.

Language-native clients (`reqwest`, `fetch`, Python's `urllib.request`) do not
work: there are no sockets and no `wasi:http/outgoing-handler`. Use this.

### `devices`

Your plugin's devices. Needs `devices = true`. Ids are `room/name`. Full
treatment in [devices](/docs/writing-add-ons/devices).

```rust
use niles::integration::devices;
use niles::integration::types::{Device, DeviceClass, LightCapabilities};

devices::upsert(&Device {
    id: "living_room/floor_lamp".into(),
    class: DeviceClass::Light,
    light: LightCapabilities { color_temp: true, rgb: false },
    controllable: true,
    state: empty_state(),
})
.map_err(|e| format!("{e:?}"))?;

let mut state = empty_state();
state.on = Some(true);
state.brightness = Some(60);
devices::report_state("living_room/floor_lamp", &state);

devices::report_action("hall/button", "single");
devices::report_action("office/printer", "finished");
devices::set_available("living_room/floor_lamp", false);
devices::set_room_light("office/chamber_light", false);
devices::remove("living_room/old_lamp");
let mine: Vec<String> = devices::registered();
```

Any class may `report_action`, not only a `switch`
([actions](/docs/writing-add-ons/devices#actions)). `set_room_light` (0.2.1) keeps a light out
of its room's lights: room and house commands, scenes, presence, the curve
and the morning routine ([lights and the room](/docs/writing-add-ons/devices#lights-and-the-room)).

### `timers`

```rust
use niles::integration::timers;

timers::every("poll", 60);    // on_timer("poll") every 60 s, first in 60 s
timers::after("retry", 30);   // once, in 30 s
timers::cancel("retry");
```

`every` is at least 5 s, `after` at least 1 s. At most 32 timers. A timer with
the same id replaces the old one. Timers do not survive a restart of the
instance, which always runs `init` again, so set them there. If you want a
first run straight away, call your handler at the end of `init`.

### `events`

Things happening elsewhere in the house, delivered to `on_event`. Each kind
must be listed under `events` in the manifest's permissions.

```rust
use niles::integration::events;
use niles::integration::types::EventKind;

events::subscribe(EventKind::DeviceState, &["office/*".to_string()]);
events::subscribe(EventKind::Presence, &[]);
events::unsubscribe(EventKind::DeviceAction);
```

- `DeviceState`: another device's state changed. You get its full id
  (`z2m:office/door`), class, and only the fields that changed — including
  only the [readings](/docs/writing-add-ons/devices#readings) that changed, so a plug's `power`
  arrives without its `energy`.
- `DeviceAction`: a button or wall switch was pressed. `action` uses
  Zigbee2MQTT's words: `single`, `double`, `hold`, `on_press`, `up_hold`…
- `Presence`: the house became `Home`, `Away` or `Unknown`. Never who.

The patterns narrow device events by `room/name`: `office/door`, `office/*`,
`*/door`; an empty list means every device. You never get events for your own
devices. At most 256 events wait for you; past that the oldest are dropped and
the count is shown on your card, so keep `on_event` quick.

### `notify`

Speak through the satellites by way of Niles's notifications. This interface
is available in 0.5 and 0.6; the tracked calls are 0.6-only. Needs
`notify = true`; `Urgent` needs `notify = "urgent"`.

```rust
use niles::integration::notify;

// Legacy 0.5 API: Ok means accepted, not delivered.
notify::say("The washing machine is done.", notify::Priority::Normal, Some("kitchen"));
```

- `room` names a room. In interface 0.6, omitting it targets the whole house.
  A named room must be a known, routed room; an unknown or unrouted room is
  refused with a named explanation, not silently redirected.
- One or two short sentences, the important part first. It is spoken by a
  text-to-speech voice: write numbers and units as words would be read
  ("twenty degrees"), skip symbols and URLs.
- A shared quota of 6 per hour applies per plugin to `say` and `request`;
  status reads do not consume quota. `say` is the legacy API: success means
  accepted, not delivered.

Interface 0.6 adds tracked requests:

```rust
let request = notify::request("The washing machine is done.", notify::Priority::Normal, Some("kitchen"))?;
match notify::status(request)? {
    notify::RequestStatus::Pending => { /* check again later */ }
    notify::RequestStatus::Completed => { /* host transport write completed */ }
    notify::RequestStatus::Partial | notify::RequestStatus::Suppressed
    | notify::RequestStatus::Failed => { /* report or handle the outcome */ }
}
```

Statuses are `pending`, `completed`, `partial`, `suppressed` and `failed`.
`completed` means the host transport write completed, not that audio played
or was heard. A request is accepted before delivery begins and times out after
20 seconds as `failed`. Each plugin instance can retain at most 32 records,
including pending requests; terminal records are retained for five minutes.
Request ownership is isolated to the instance. Teardown cancels outstanding
work and removes its records. A socket write already in progress may still
finish after cancellation or timeout; neither those bytes nor already-buffered
audio can be retracted. A failed result is not proof that no audio was sent.
Quiet-hours handling does not promise replay later.

### `speech-stream`

Interface 0.5 adds room-bound commentary, separate from `notify`. It needs
`speech_stream = { room = "room" }` in `[permissions]` and a boolean setting named
`speech_stream_enabled` with no default or `default = false`. The permission
must reference a declared `type = "room"`
setting. The household must turn the boolean on and choose that room. `open`
accepts only the current saved room value. See [permissions](/docs/writing-add-ons/permissions#frequent-spoken-commentary).

```rust
let room = match config::get("room") {
    Some(config::SettingValue::Text(room)) => room,
    _ => return Err("The room is not set.".into()),
};
let session = speech_stream::open(&room)?;
let request = speech_stream::submit(session, "The printer finished.")?;
// Poll speech_stream::poll(session) until this request has a terminal outcome.
speech_stream::close(session);
```

`open` reserves one session for the plugin instance and fixes its room. A
successful open confirms that the household-selected room has a configured
satellite route. It does not guarantee that the satellite is connected or that
audio will be heard. Busy and quiet-hour policy is checked when work is submitted.
`submit`
returns a request id when the host accepts work, not when it finishes or is
heard. Poll for ordered terminal outcomes: `delivered`, `busy`, `quiet`,
`expired`, `failed`, `cancelled`, `replaced`, `rate-limited` or `no-satellite`.
`delivered` means the host completed its transport write, not that a person
heard it. Poll consumes completed records; pending records stay queued.

- `busy`: somebody is talking to Niles in that room, a notification is being
  spoken there, or another add-on's commentary is playing. Try again later.
- `cancelled`: a voice turn or a notification took the room over while this
  was being prepared or sent, or the session was closed.
- `failed`: synthesis or the transport to the satellite failed. Waiting will
  not help.
- `quiet`: quiet hours.

Text must be nonblank and no more than 120 characters. A session retains at
most 32 uncollected request results. A newer accepted request replaces older
work that has not started transport, including speech still being synthesized;
the replaced request reports `replaced`. Transport already started is not replaced.
Requests expire after three seconds if transport has not started. The host limits
each add-on owner to 120 admitted requests per rolling 60 seconds; closing and
reopening a session does not reset that quota. Excess work reports `rate-limited`.
Excess submissions fail with `limit`; invalid text fails with `invalid`.
Permission and ownership errors are `not-permitted`. A household that has
turned the stream off, or a session that is still open elsewhere, is an
`unavailable` host error from `open` or `submit`; busy rooms and quiet hours
come back as outcomes from `poll`, never as host errors.

`close` is idempotent and cancels accepted work. Poll cancellation results
before opening another session. The host reserves the plugin's session until
its worker stops; instance teardown closes it and discards results that no
plugin instance can collect. Commentary does not use notification quotas,
chimes, history or priority. Interactive voice preempts synthesis and pending
delivery on a best-effort basis. Audio already buffered by the satellite
cannot be recalled by the current Wyoming protocol.

### `ui`

The node types for pages and widgets, and one function:

```rust
use niles::integration::ui;

ui::invalidate("electricity");
```

which asks every app showing that surface to render it again. Cheap; see
[pages and widgets](/docs/writing-add-ons/ui#refresh).

### `mqtt`

New in 0.2. Connections to the brokers your manifest's `mqtt` permission
names, held by Niles: it reconnects with a backoff and subscribes again, and
nothing here waits on the network.

```rust
use niles::integration::mqtt::{self, ConnectOptions, Qos};
use niles::integration::types::HostError;

let conn = mqtt::connect("printer", &ConnectOptions {
    client_id: None,
    username: Some("bblp".into()),
    password: config::secret("access_code"),
    keep_alive: None,
    clean_session: None,
})
.map_err(|e| format!("{e:?}"))?;
let fail = |e: HostError| format!("{e:?}");
mqtt::subscribe(conn, "device/+/report", Qos::AtMostOnce, false).map_err(fail)?;
let pushall = br#"{"pushing":{"sequence_id":"0","command":"pushall"}}"#;
mqtt::publish(conn, "device/01S00A/request", pushall, Qos::AtMostOnce, false).map_err(fail)?;
mqtt::unsubscribe(conn, "device/+/report").map_err(fail)?;
mqtt::accept_certificate(conn).map_err(fail)?; // only after asking the household
mqtt::disconnect(conn);
```

At most 4 connections, 64 subscriptions each, 256 KiB a message, 20 publishes
a second. `publish` fails with `unavailable` while the connection is down.
The full story, with the address rules and `trust-device` certificates, is in
[MQTT](/docs/writing-add-ons/mqtt).

### `secrets`

New in 0.3. Credentials the plugin keeps itself, such as an OAuth token it
refreshed, in Niles's encrypted secret store. `storage` is plain text in
Postgres: it is no place for a token.

```rust
use niles::integration::secrets;

secrets::set("token", &serde_json::to_string(&pair)?).map_err(|e| format!("{e:?}"))?;
let pair: Option<String> = secrets::get("token");
secrets::delete("token").map_err(|e| format!("{e:?}"))?;
```

- **`set` is atomic.** It returns `ok` once the value is kept; on `err` the
  previous value is still there. Keep what changes together (an access
  token, its refresh token, when it expires) in one value, as JSON.
- Keys are `[a-z0-9_]+`, at most 64 bytes; at most 16 keys, of at most 4 KiB
  each. Past either, `limit`; the store not answering, `unavailable`.
- Not your settings: nothing here appears on the setup panel, and
  `config.secret` reads only the `secret` settings the household typed in.
- Removed with the plugin. Without a secret store (no database) they are
  kept in memory and lost on a restart.

### `inbound`

New in 0.3, with the `webhook` permission.

```rust
use niles::integration::inbound;

let address: Option<String> = inbound::hook_url();
// "https://home.example.dk/plugins/withings/hook/9f2c…"
```

The webhook's full address, to give the service that calls it, from
`init`. None until the household sets Niles's public address; say so in
your status line. See [accounts and webhooks](/docs/writing-add-ons/accounts#the-webhook).

### WASI

Toolchains import parts of WASI 0.2 whether you use them or not, so Niles
provides them, empty. What works: the wall clock and monotonic clock
(`SystemTime::now()`, `Instant`), randomness, stdout and stderr (to your log).
What does not: files (no directories exist), environment variables (none),
sockets and DNS (refused), `std::process`, threads.

## Outside the host API

Raw TCP and UDP, `wasi:http/outgoing-handler`, plugin-owned HTML pages, and
on-demand reads of other devices' state are not provided by this host API.
